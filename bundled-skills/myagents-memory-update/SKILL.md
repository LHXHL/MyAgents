# MyAgents Memory Update

在当前 Session 内直接完成一次工作记忆沉淀。目标不是复述聊天记录，而是让未来
Session 仅通过工作区，就能准确接续这里发生过的关键事实、决定、状态和经验。

## 范围

- 只回顾当前 Session 自上次成功记忆更新后新增的工作。
- 只处理当前 Session 的工作记忆、相关工作区产物及其直接造成的修正。
- 直接执行本流程，不新建 Session，不委派给子 Agent，也不转交其它维护流程。
- 保留用户的既有文件和无关未提交改动；不要为了整理而扩大任务范围。

## 工作流程

1. 深度回顾当前 Session，提取会影响未来工作的事实、决策、状态变化、用户偏好、
   约束、踩坑经验和明确的后续线索。忽略寒暄、重复信息和已经失效的过程噪音。
2. 阅读工作区当前的记忆系统原则与结构，包括适用的 `.claude/rules/` 文件、
   `memory/` 目录及工作区自定义维护要求；以工作区既有结构为权威，不强行套用
   不存在的目录或命名。
3. 检查当前 Session 创建或修改的工作区产物。保留仍有用途的文件；对临时、散落、
   重复或位置不合适的产物做适当归档、合并、重命名或清理。不要碰无关产物。
4. 按工作区结构沉淀记忆：原始时序信息进入当日日志，单一项目或主题的细节进入
   topic 文件，跨 Session 都必须记住的稳定信息进入核心记忆。信息只保留一个权威
   落点，其他层使用简短指针，避免重复堆积。
5. 如果本次 Session 使既有记忆过时、错误或互相冲突，直接修正或删除旧条目；不要
   只追加一条新说明，把矛盾留给未来 Session。
6. 在工作区约定的日志位置记录本次维护，说明沉淀了什么、修正了什么，以及仍需
   未来跟进的事项。没有值得长期保留的信息时，也要完成产物检查，但不要制造空洞
   的“已更新”内容。
7. 完成文件整理与记忆写入后处理 Git：
   - 如果不是 Git 仓库，跳过 Git 操作。
   - 如果没有本次流程产生的相关变更，不创建空提交，也不 push。
   - 如果有相关变更，只 stage 当前 Session 及本次维护直接产生或修改的文件；不得
     stage 工作区原有或并发产生的无关改动。
   - 提交当前相关变更，并 push 当前分支到其已配置的远端。不要切换分支，不要改写
     历史，不要 force push。
   - 如果无法安全区分相关变更，或 commit / push 失败，保留现场并明确视为本次流程
     未完成，不得报告成功。

## 完成条件

只有以下条件全部成立，才算完成：

- 当前 Session 的关键工作记忆已按工作区原则落盘。
- 当前 Session 的相关工作区产物已做适当整理。
- 被本次 Session 直接推翻的旧记忆已得到修正。
- Git 仓库中的本次相关变更已按上述边界 commit 并成功 push；或确认没有相关变更。

调用方会规定最终成功标记。完成全部操作后严格遵守该输出要求；任何必要步骤失败时，
不要伪造成功标记。
