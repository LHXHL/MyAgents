# Agent 网络与即时 Session 协作

## 选择哪种协作

| 用户目标 | 使用路径 |
|---|---|
| 让本机另一个 Workspace Agent 立即做事 | 发现 Agent，使用 Session start/send |
| 让同账号另一台设备上的 Agent 立即做事 | Agent 网络 + 同一套 Session 命令 |
| 读取或观察已有工作，不分配新任务 | Session get/state/watch |
| 需要定时、独立任务状态、审计与验收 | Task，见 `automation.md` |
| 团队指派、认领、评论与共享资源 | 协作空间 Issue / Registered Agent，见 `cloud-space.md` |
| 从 Telegram、钉钉、飞书等收发消息 | Agent Channel，见 `agents-channels.md` |

Agent 网络是同账号设备间的在线协作能力。开放 Agent 不等于注册 Space Agent，也不等于打开 heartbeat、记忆维护或 IM Channel。

## 入口与前置条件

1. 从侧栏「更多 → Agent 网络」进入，使用 MyAgents 账号登录。
2. 确认目标设备登录同一账号，并加入网络。
3. 在设备详情中选择要开放的工作区 Agent，填写适合其它 Agent 理解的描述。
4. 目标设备需在线、应用运行且目录已同步；本机目标模型、工具与权限也需可用。

入网后默认不开放任何 Agent。退出网络会清空开放设置，重新加入后需再次选择；工作区归档也会使原开放授权失效。设备加入网络、在线、目录同步和 Agent 开放是不同事实，页面按这些事实显示状态。离线设备可以管理设置，但不代表能立即执行。

登录同账号的来源设备可以主动调用目标开放的 Agent，不必为本次调用和结果回传先入网或开放自己的 Agent。设备列表展示开放 Agent 及数量；设备详情可单独重试失败的目录读取。

## `@` 选择与实际调用

输入 `@` 后可选本机或远端 Agent、想法与文件。空关键词展示 Agent 和想法；有关键词后按 Agent → 想法 → 文件排列，各组可以展开更多。远端名称、描述、来源设备和图标用于帮助选择，未知图标显示机器人。

首屏结果共用加载状态，最多等待两秒；超时仍可显示已取得的结果并标明不完整，主动重试可获取新目录。打开中的面板不会持续插入后来到达的结果，重新打开可刷新。文件只从当前工作区发现，远端 Agent 不会把其整个文件树变成本机附件来源。

选择 Agent 引用是给模型提供目标信息；真正分配工作由 Session 命令完成。发送和重试时重新核对目录与账号，不能按同名对象猜目标，也不能把过期引用当永久授权。需要操作时加载 `/myagents-cli`。

## 命令怎样选择

- `agent list/show`：发现目标并查看身份和未来 Session 的默认配置；复制完整 Agent ID。
- `session list --agent`：查可复用历史上下文，不证明此刻正在运行。
- `session start`：在目标 Agent 下创建新的隔离 Session。
- `session send`：在已知 Session 中继续工作，保留它的上下文。
- `session get`：分页读取可见用户/协作请求与 assistant 正文，不输出思考、工具参数或隐藏结果控制事件。
- `session state`：按需只读 `idle / running / waiting_user_action`，不启动 AI。
- `session watch`：一次性观察真实执行轮次；`session watches/unwatch` 管理当前调用方的观察。

远端 ID 是完整的 `ma-agent:1:...` 或 `ma-session:1:...` 标识。只能使用发现结果中的完整值，不截短、不用文件路径或名称替代。远端配置、审批和文件管理不通过这些命令开放。

## 接纳、消费、完成与回传

`start/send` 成功表示请求已接纳，不表示模型已消费或工作已成功完成。目标使用自己的 Session 配置与权限；调用方不能覆盖其模型、Runtime、工具或审批策略。`agent show` 的出生默认也不能证明已有 Session 当前的权限。

App 内真实 Session 发起的请求默认在目标轮次结束后回传结果，可用 `--no-reply` 关闭。外部终端/AI 必须先获本机「外部调用」授权，按公开命令运行；其 start/send 为单向投递，没有来源 Session 的自动回传或 watch，见 `settings-safety.md`。

Inbox 与手动输入的队列响应设置独立：可信协作输入可在 Runtime 支持的安全点实时进入当前轮次，手动排队消息仍等自己的轮次。结果只归给实际消费它的轮次；未消费的请求不能借用上一轮结果。

默认回传通常不需要再注册 watch。同一调用方对同一目标轮次的重复观察可合并，自动回传与该轮观察协调为一次通知；不同请求仍有自己的关联。取消观察不会停止目标、取消默认回传或撤回已接纳消息。

`waiting_user_action` 表示目标需要它自己的用户审批、确认计划或回答必答问题；来源不能远程代批。`idle` 只表示当前无活跃工作，不证明成功。空闲 watch 返回最近 Session 结果，并区分 live/history/none/unavailable 与已知完成、停止、失败状态，不能当作某次请求的确定答案。

## 连接与数据边界

- 这是在线通信，没有云端离线消息队列或断线后的补投。真实断线或账号变化会失去当前回传关联；目标已接纳的工作仍可继续。
- start/send 回执丢失或接纳未知时，保留请求与 Session ID，先读目标状态/历史，不自动重发，避免重复执行。只读查询失败可按提示重试。
- 业务请求、响应、会话正文和结果在设备之间使用 TLS 1.3 双向认证加密；目录、设备状态和有界路由元数据不属于这一正文范围。
- 私钥由系统凭据库保存，不要求用户粘贴 token，也不通过编辑内部网络 store 修复。
- 客户端、云端与协议产物分别维护；遇到兼容错误需核对双方版本和协议。开发版功能存在不能证明服务已部署或旧设备兼容。

## 什么时候转入 support

目标在线且开放后仍无法发现/调用、结果回到错误 Session、观察取消后反复通知、读取与界面正文冲突，或状态查询与目标实际交互不符。先保留双方设备/版本、完整 selector、requestId、Session/turn/watch ID、操作时间和错误 code，再进入 `/support` 的 Agent 网络诊断；不要通过再发一次工作来测试查询故障。
